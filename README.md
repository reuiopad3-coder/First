# ⭐️ Telegram Stars Bot

Профессиональный Telegram-бот для автоматизированной продажи **Telegram Stars** с приёмом платежей через **CryptoBot (Crypto Pay API)**, расчётами в **USDT**, защитой от двойной выдачи звёзд, фоновым поллингом оплат и полнофункциональной панелью администратора.

---

## 🛠 Технологический стек

- **Язык:** Python 3.11+
- **Фреймворк:** [aiogram 3.x](https://github.com/aiogram/aiogram) (полностью асинхронный)
- **База данных:** [SQLAlchemy 2.0 Async](https://www.sqlalchemy.org/) (SQLite с `aiosqlite` по умолчанию, полная совместимость с PostgreSQL через `asyncpg`)
- **Миграции:** [Alembic](https://alembic.sqlalchemy.org/) (асинхронный движок с пакетным режимом batch DDL для SQLite)
- **Сетевой клиент:** [httpx](https://www.python-httpx.org/) (асинхронные HTTP-запросы)
- **Конфигурация:** [pydantic-settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/) (строгая валидация `.env`)
- **Антифлуд / Кэш:** [cachetools](https://github.com/tkem/cachetools) (защита от спама на базе `TTLCache`)
- **Контейнеризация:** Docker (образ `python:3.11-slim`, запуск от непривилегированного пользователя) и `docker-compose`

## ✨ Возможности

### 👤 Для пользователя:
1. **Главное меню:**
   - Быстрый просмотр актуального курса звёзд.
   - Кнопки навигации: *«Купить звёзды»*, *«Мои заказы»*, *«Поддержка»*, *«Отзывы и FAQ»*.
2. **Интерактивная покупка звёзд (FSM):**
   - Выбор готовых пакетов (50, 100, 250, 500, 1000 звёзд) или ввод своего количества (от 50 до 10 000).
   - Выбор получателя: себе (автоматический username из профиля) или в подарок по `@username`.
   - Валидация никнейма (длина 4–32, латиница, цифры, символ подчёркивания).
   - Экран подтверждения со стоимостью в USDT (расчёт через `Decimal` без погрешностей `float`).
   - Защита от двойного клика (исключено создание дублирующих счетов).
3. **Оплата через CryptoBot:**
   - Генерация инвойса со сроком жизни 15 минут.
   - Фоновый воркер проверяет оплату каждые 10 секунд (пользователю не обязательно нажимать кнопку проверки).
   - Строгая валидация статуса `paid`, валюты `USDT` и суммы.
   - При истечении 15 минут счёт помечается статусом `expired`, начисление звёзд блокируется.
4. **Выдача звёзд:**
   - Модульная архитектура: абстрактный интерфейс `StarsProvider`.
   - Готовый `MockProvider` для безопасного тестирования (эмуляция задержки, успеха и сбоев).
   - Каркас `FragmentProvider` под TON / Fragment API.
   - **Идемпотентность:** защита по `order_id` исключает двойную выдачу звёзд при повторных запросах.
   - Если провайдер вернул ошибку, заказ получает статус `failed`, администратор получает алерт, покупатель информируется о ручной обработке.
5. **История «Мои заказы»:**
   - Постраничный просмотр (по 5 заказов) со статусами: `🟢 Выполнен`, `🟡 Ожидает оплаты`, `⚫ Срок счёта истёк`, `🔴 Ошибка (в обработке)`, `⚪ Отменён`, `🟣 Возврат`.

### 👑 Для администратора (`ADMIN_IDS`):
1. **Доступ:** закрыт на уровне фильтров `IsAdminFilter` (как для текстовых команд, так и для инлайн-кнопок).
2. **Статистика:** отчёты за 24 часа, 7 дней, 30 дней и за всё время (пользователи, число заказов, оборот, выданные звёзды, выручка).
3. **Управление ценами:**
   - Команда `/setprice <базовая_цена> [наценка_%]` (например: `/setprice 0.0185 20`).
   - Интерактивное меню с валидацией границ (цена > 0 и ≤ 1.0 USDT; наценка от 0% до 500%) и отображением старых/новых значений.
4. **Управление заказами:**
   - Просмотр карточки заказа `/order_<ID>`.
   - Поиск по ID или username получателя.
   - Ручная смена статуса и оформление возврата (`refunded`) с обязательным подтверждением «Да / Нет».
   - Защита: статус `delivered` невозможно перевести обратно в `created` или `paid`.
5. **Массовая рассылка:**
   - Предпросмотр текста перед отправкой и подтверждение кнопкой.
   - Ограничение скорости (rate limiting ~20 сообщений/сек).
   - Обработка `TelegramRetryAfter` и `TelegramForbiddenError` (учёт заблокировавших бота пользователей).
   - Детальный отчёт по завершении (доставлено / заблокировали / ошибок / время).
6. **Блокировка пользователей:**
   - Команды `/ban <ID>`, `/unban <ID>` или через меню.
   - **Защита администратора:** попытка забанить админа программно блокируется.

## 🔑 Инструкция по получению токенов и ключей

### 1. Токен бота Telegram (`BOT_TOKEN`)
1. Откройте в Telegram официального бота [@BotFather](https://t.me/BotFather).
2. Отправьте команду `/newbot`.
3. Укажите название бота и его юзернейм (должен оканчиваться на `bot`, например: `my_stars_shop_bot`).
4. Скопируйте полученный токен (вида `1234567890:ABCdefGHI...`) в переменную `BOT_TOKEN`.

### 2. Ваш Telegram ID (`ADMIN_IDS`)
1. Откройте бота [@userinfobot](https://t.me/userinfobot) или [@myidbot](https://t.me/myidbot).
2. Отправьте ему любое сообщение — бот вернёт ваш числовой `Id` (например, `123456789`).
3. Впишите этот ID в переменную `ADMIN_IDS`. Если админов несколько, укажите их через запятую: `123456789,987654321`.

### 3. Токен CryptoBot (`CRYPTOBOT_TOKEN`)

#### А. Для тестов без денег (Testnet — рекомендуется для старта):
1. Откройте тестового бота [@CryptoTestnetBot](https://t.me/CryptoTestnetBot).
2. Отправьте команду `/pay` ➔ нажмите **«Create App»**.
3. Задайте имя приложения и нажмите **«API Token»**.
4. Скопируйте токен в `CRYPTOBOT_TOKEN` и убедитесь, что указано:
   ```env
   CRYPTOBOT_NETWORK=testnet
   STARS_PROVIDER=mock
   ```

#### Б. Для боевой работы (Mainnet):
1. Откройте официального бота [@CryptoBot](https://t.me/CryptoBot).
2. Отправьте команду `/pay` ➔ нажмите **«Создать приложение»**.
3. Скопируйте токен в `CRYPTOBOT_TOKEN` и установите:
   ```env
   CRYPTOBOT_NETWORK=main
   ```

## 🚀 Установка и локальный запуск

### Шаг 1. Клонирование репозитория и создание виртуального окружения
```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd telegram_stars_bot

# Создание виртуального окружения Python 3.11+
python -m venv venv

# Активация окружения (Windows PowerShell):
.\venv\Scripts\Activate.ps1

# Активация окружения (Linux / macOS):
source venv/bin/activate
```

### Шаг 2. Установка зависимостей
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### Шаг 3. Настройка файла `.env`
Скопируйте шаблон:
```bash
# Windows:
copy .env.example .env

# Linux / macOS:
cp .env.example .env
```
Откройте файл `.env` в текстовом редакторе и заполните:
```env
BOT_TOKEN=1234567890:ABCdef...
ADMIN_IDS=123456789
CRYPTOBOT_TOKEN=вас_токен_cryptobot
CRYPTOBOT_NETWORK=testnet
STARS_PROVIDER=mock
```

### Шаг 4. Применение миграций базы данных
```bash
alembic upgrade head
```

### Шаг 5. Запуск бота
```bash
python -m bot
```

## 🐳 Запуск через Docker и Docker Compose

Бот полностью упакован для запуска в изолированном контейнере с непривилегированным пользователем `appuser` и монтированием томов для сохранения базы данных и логов.

### 1. Подготовка `.env` для Docker
Убедитесь, что в `.env` база данных настроена на запись в примонтированный том `data/`:
```env
DATABASE_URL=sqlite+aiosqlite:///data/bot.db
```

### 2. Запуск контейнера
```bash
docker compose up -d --build
```
*При запуске контейнера скрипт `entrypoint.sh` автоматически наложит миграции `alembic upgrade head` и запустит бота.*

### 3. Просмотр логов контейнера
```bash
docker compose logs -f stars-bot
```

### 4. Остановка контейнера
```bash
docker compose down
```

## 🚂 Развёртывание на Railway

Бот оптимизирован для деплоя на [Railway](https://railway.app):

1. **Создайте проект на Railway** и подключите ваш репозиторий GitHub.
2. Railway автоматически обнаружит `Dockerfile` и соберет проект.
3. **Настройка переменных среды (Variables):**
   В панели Railway добавьте переменные из вашего `.env`:
   - `BOT_TOKEN`
   - `ADMIN_IDS`
   - `CRYPTOBOT_TOKEN`
   - `CRYPTOBOT_NETWORK` (`testnet` или `main`)
   - `STARS_PROVIDER` (`mock` или боевой)
4. **Сохранение данных:**
   - **Вариант А (PostgreSQL на Railway — рекомендуется):**
     Добавьте в Railway плагин **PostgreSQL**. Railway автоматически создаст переменную `DATABASE_URL`. Измените в ней протокол на асинхронный: `postgresql+asyncpg://...` вместо `postgresql://...`.
   - **Вариант Б (SQLite через Volume):**
     Добавьте в Railway сервис **Volume**, смонтируйте его по пути `/app/data` и укажите `DATABASE_URL=sqlite+aiosqlite:///data/bot.db`.

## 🛡 Аудит безопасности и надёжности

- **Защита секретов:** токены `BOT_TOKEN` и `CRYPTOBOT_TOKEN` маскируются и **никогда не выводятся в логи**. В репозитории и Docker-образе секреты отсутствуют благодаря строгим правилам `.gitignore` и `.dockerignore`.
- **Финансовая строгость:** суммы заказов и цен хранятся в формате `Decimal` (`Numeric(10, 4)` и `Numeric(10, 2)`), исключая проблемы с округлением чисел с плавающей точкой (`float`).
- **Строгая проверка платёжки:** платёж подтверждается только при совпадении трёх факторов: статус `paid`, валюта `USDT` и сумма не меньше суммы заказа.
- **Идемпотентность:** повторные вызовы выдачи для одного и того же `order_id` блокируются программно.
- **Отказоустойчивость:** фоновый воркер `PaymentPollingWorker` защищён блоками перехвата исключений и не падает при временных обрывах связи с API.
- **Разграничение прав:** админские роутеры защищены `IsAdminFilter`, обычные пользователи не могут вызвать ни команды, ни callback-запросы админки.
- **Защита от флуда:** `ThrottlingMiddleware` отсекает спам-запросы пользователей.
